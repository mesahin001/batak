## Directory Purposes

**server/src/game/:**
- Purpose: All core game rules and logic
- Contains: State machine, card comparison, scoring formulas, turn validation
- Key files: `GameStateMachine.ts` (central hub), `TurnValidator.ts` (move validation), `Scoring.ts` (score calculation), `Player.ts` (state mutations)

**server/src/socket/:**
- Purpose: WebSocket server and event routing
- Contains: Socket.IO initialization, per-client event listeners, state broadcasting
- Key files: `SocketServer.ts` (all event handlers), handlers subdirectory for modular logic, `RedisAdapter.ts` for distributed mode

**server/src/matchmaker/:**
- Purpose: Queue management and room lifecycle
- Contains: Player queue, timeout-based bot fallback, room creation/destruction
- Key files: `Matchmaker.ts` (60s PvP wait, 30s mixed mode, instant bot games)

**server/src/bots/:**
- Purpose: Bot player AI and move selection
- Contains: Hand analysis (strength evaluation), three difficulty strategies, turn timing
- Key files: `BatakBot.ts` (manager), `HandAnalyzer.ts` (hand evaluation), `strategies/` (Easy/Normal/Hard)

**server/src/auth/:**
- Purpose: Authentication service
- Contains: Email registration/login, wallet token generation, JWT handling
- Key files: `AuthService.ts` (only file; bcryptjs for passwords, jsonwebtoken for tokens)

**server/src/database/:**
- Purpose: Data persistence
- Contains: SQLite schema and queries
- Key files: `DatabaseManager.ts` (wrapper for better-sqlite3)

**server/src/solana/:**
- Purpose: Blockchain integration
- Contains: cNFT minting, Merkle tree management, Solana RPC client
- Key files: `CNFTMinter.ts`, `TournamentManager.ts`, `MerkleTreeManager.ts`

**client/src/components/:**
- Purpose: React UI components
- Contains: Game UI (GameRoom), lobby, auth screens, leaderboard, results
- Key files: `GameRoom.tsx` (main game), `GameRoom.css` (grid-based layout), `Lobby.tsx` (matchmaking queue)

**client/src/auth/:**
- Purpose: Client-side authentication state
- Contains: Login/register flows, token persistence, wallet integration
- Key files: `AuthContext.tsx` (unified auth interface for email + wallet)

**client/src/socket/:**
- Purpose: WebSocket client and event management
- Contains: Socket.IO connection, auto-reconnect, provider setup
- Key files: `SocketContext.tsx` (connection manager, event subscription)

**mobile/src/screens/:**
- Purpose: Full-screen React Native components
- Contains: Auth flows, lobby, game screen, results
- Key files: `game/GameRoomScreen.tsx` (main game UI)

**mobile/src/contexts/:**
- Purpose: Mobile context providers
- Contains: Auth, Socket, Wallet contexts (analogous to web client)
- Key files: Match web counterparts in functionality

## Key File Locations

**Entry Points:**
- `server/src/server.ts`: Server startup, HTTP/WebSocket initialization
- `client/src/main.tsx`: React DOM render entry point
- `mobile/App.tsx`: Expo entry point
- `solana-program/programs/batak-tournament/src/lib.rs`: Solana program entry

**Configuration:**
- `server/src/config.ts`: Environment validation, defaults
- `server/.env`: Server secrets (port, JWT_SECRET, Solana keys)
- `client/.env`: Client config (VITE_SERVER_URL, Solana network)
- `mobile/.env.example`: Mobile template
- `docker-compose.yml`: Production deployment config

**Core Logic:**
- `server/src/game/GameStateMachine.ts`: Central game state machine (LOBBY → BIDDING → PLAYING → SCORING → FINISHED)
- `server/src/game/TurnValidator.ts`: Move validation (card exists? suits followed? trump rules?)
- `server/src/game/Scoring.ts`: Score calculation (Batak rules for Koz Maca and Ihaleli)
- `server/src/socket/SocketServer.ts`: All Socket.IO event handlers
- `server/src/matchmaker/Matchmaker.ts`: Room and queue management

**Testing:**
- `server/src/game/__tests__/GameFlow.test.ts`: End-to-end game flow
- `server/src/game/__tests__/TurnValidator.test.ts`: Move validation
- `server/src/game/__tests__/Scoring.test.ts`: Score calculation (8 failures in ihaleli_batak mode — expected)
- `server/src/bots/__tests__/`: Bot AI tests

## Naming Conventions

**Files:**
- **Components:** PascalCase (e.g., `GameRoom.tsx`, `AuthScreen.tsx`)
- **Services/Utilities:** PascalCase (e.g., `AuthService.ts`, `DatabaseManager.ts`)
- **Context:** PascalCase with "Context" suffix (e.g., `AuthContext.tsx`, `SocketContext.tsx`)
- **Test files:** `.test.ts` or `.spec.ts` suffix
- **Styles:** Match component name, `.css` suffix (e.g., `GameRoom.css`)

**Functions:**
- **Functional components:** PascalCase (e.g., `GameRoom()`, `Lobby()`)
- **Hooks:** camelCase with "use" prefix (e.g., `useAuth()`, `useSocket()`)
- **Utility functions:** camelCase (e.g., `calculateScores()`, `dealCards()`)
- **Event handlers:** camelCase, "on" or "handle" prefix (e.g., `handlePlayCard()`, `onJoinQueue()`)

**Variables:**
- **Constants:** UPPER_SNAKE_CASE (e.g., `TOTAL_ROUNDS_OPTIONS = [5, 7, 9, 11]`)
- **State variables:** camelCase (e.g., `gameState`, `isLoading`)
- **Private fields:** camelCase with underscore prefix in classes (e.g., `private _socket`)

**Types:**
- **Enums:** PascalCase (e.g., `GameState.LOBBY`, `PlayerType.BOT`, `Suit.SPADES`)
- **Interfaces:** PascalCase with optional "Type" or "Props" suffix (e.g., `PlayerState`, `GameRoom`, `SocketContextType`)
- **Type aliases:** PascalCase (e.g., `type AppState = 'loading' | 'auth' | ...`)

## Where to Add New Code

**New Feature (e.g., new game mode, new scoring rule):**
- **Primary logic:** `server/src/game/` (update GameStateMachine.ts, TurnValidator.ts, Scoring.ts as needed)
- **Tests:** `server/src/game/__tests__/` (add GameFlow.test.ts, Scoring.test.ts cases)
- **Client UI:** `client/src/components/` and `mobile/src/screens/game/`
- **Socket events:** Add new ClientEvent in `server/src/types/socket.ts`, handler in `SocketServer.ts`

**New Component/Module:**
- **Web component:** `client/src/components/` (PascalCase.tsx + PascalCase.css)
- **Mobile screen:** `mobile/src/screens/` (subdirectory by feature, e.g., `screens/newfeature/NewFeatureScreen.tsx`)
- **Service/Utility:** Subdirectory of `server/src/` matching domain (e.g., `server/src/analytics/AnalyticsService.ts`)

**New Bot Strategy:**
- **File:** `server/src/bots/strategies/{Difficulty}Strategy.ts` (implement `selectCard()` and `selectBid()`)
- **Register:** Update `BatakBot.ts` constructor to wire difficulty to strategy

**Shared Utilities:**
- **Server helpers:** `server/src/` (create subdirectory if >1 file, e.g., `utils/`, `helpers/`)
- **Client helpers:** `client/src/` (top-level utility files or `utils/` subdirectory)
- **Mobile helpers:** `mobile/src/` (match web structure for parity)

**Types/Interfaces:**
- **Game types:** `server/src/types/game.ts` (shared with clients)
- **Socket event types:** `server/src/types/socket.ts`
- **Client-specific types:** `client/src/types/` (extend game types as needed)
- **Mobile-specific types:** `mobile/src/types/` (reuse server types where possible)
